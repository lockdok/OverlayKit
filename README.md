# OverlayKit

OverlayKit is a Windows companion app that captures global keyboard and mouse activity and displays it in an OBS browser source. The initial release is Windows-only.

## Performance

- Input hooks only enqueue small events and never wait for the browser source or disk I/O.
- Events are discarded while no browser source is connected. A slow or stalled browser source is disconnected instead of delaying input capture.
- The OBS page avoids backdrop blur and keeps recent-key elements bounded, which reduces compositing and DOM work during rapid gameplay input.

## Privacy and input filtering

- The app does not read text from applications or collect typed strings.
- Letter, number, space, and punctuation keys are hidden unless Ctrl, Alt, or Win is held. Shift is displayed as a modifier, but Shift alone does not expose typed characters. When part of a shortcut, only the key name is sent (for example, `Ctrl` and `C`), never the text generated by the keystroke.
- Printable key names are also hidden while Right Alt and left Ctrl are held together, which avoids exposing characters typed with the AltGr layout modifier.
- Modifier keys, F1–F12, and named non-printing keys can be shown when pressed on their own.
- Keyboard and mouse events are sent only to browser clients connected to the companion app on `127.0.0.1`; WebSocket connections from other browser origins are rejected.
- The app uses Windows low-level hooks and passes input through; it does not block or modify keystrokes or mouse actions.
- Capture stops when the companion app is closed. A visible connection status appears in the control page and browser source.

## Run from source

1. Install the .NET 8 SDK on Windows.
2. In this folder, run `dotnet run`.
3. Open [http://127.0.0.1:17893/](http://127.0.0.1:17893/) to configure the overlay.
4. In OBS, add a **Browser** source and use:
   `http://127.0.0.1:17893/?mode=overlay`
5. Set the source dimensions to fit your scene. Keep the companion app running while the source is in use.

The control page lets you switch between a compact text display and a highlighted keyboard layout, show or hide the keyboard and mouse independently, and set the fade time for recent input. Adjust horizontal and vertical position within the OBS Browser source, resize the layout, and customize its font family, font size, text, accent, and key colors, panel color, and panel opacity. Position sliders align the corresponding point on the overlay with that percentage of the source, so it stays on-screen when resized. Settings are stored in `%LOCALAPPDATA%\OverlayKit\settings.json`. Existing settings in `%LOCALAPPDATA%\OBSInputOverlay\settings.json` are migrated automatically when OverlayKit starts.

For troubleshooting a port conflict, set the `OVERLAYKIT_PORT` environment variable to an available port from `1024` to `65535` before starting the app. The control page shows the matching OBS Browser source URL.

Mouse clicks (LMB, MMB, RMB) highlight their corresponding area on the mouse diagram. Vertical and horizontal scroll direction is shown briefly next to it.

## Build

From a Windows terminal with the .NET 8 SDK:

```powershell
dotnet build -c Release
```

The browser-source files are copied next to the app in the build output. The app listens only on loopback at `127.0.0.1:17893`; if the port is in use, close the other app using it before starting this one.

## Download a release

Download the latest **OverlayKit-windows-x64** ZIP from the [GitHub Releases page](https://github.com/lockdok/OverlayKit/releases/latest). Extract the whole ZIP to a folder and run `OverlayKit.exe`. This is a self-contained Windows x64 build and does not require a separate .NET installation. Keep the `wwwroot` folder next to the executable; it contains the control page and OBS overlay files.

The OBS Browser source URL remains `http://127.0.0.1:17893/?mode=overlay`. Keep OverlayKit running while the source is in use.
